# מדריך: מדידת שני SDR בבית — צעד אחר צעד

> נוהל ההרצה של `scripts/airam-dual-sdr-probe` (שלב 0 ב-`docs/dual-sdr-feasibility.md` §7).
> זמן כולל: **כ-40 דקות**, מתוכן ~22 דקות שבהן לא עושים כלום חוץ מלחכות.

---

## צריך לצאת לשטח? — לא

הבדיקה שואלת שלוש שאלות, ואף אחת מהן לא תלויה במקום:

| השאלה | תלויה במה | תלויה במקום? |
|-------|-----------|---------------|
| ה-Pi מחזיק חשמלית שני מקלטים? | **ספק הכוח והכבל** | לא |
| ה-USB וה-CPU עומדים בקצב? (overflow) | ה-Pi עצמו | לא |
| שני המקלטים באמת מזרימים נתונים? | המקלטים | לא — עובד גם בלי אנטנה |

**התנאי היחיד:** להריץ על **אותו ספק כוח ואותו כבל** שאיתם תצא לשטח (ה-power bank).
זה כל העניין — ספק אחר בבית ייתן תשובה על ספק אחר.

מה הבית **לא** יגיד לך: כמה הודעות ACARS תקלוט. אם אתה רחוק משדה תעופה, סביר שתראה
אפס הודעות — זה נרשם כהערה, **לא** ככישלון.

---

## מה צריך להכין

- [ ] ה-Pi עם AIR-AM מותקן ועובד.
- [ ] **RSP1B** (המקלט הרגיל שלך) + **RSP1A** (החדש).
- [ ] שני כבלי USB למקלטים.
- [ ] **ה-power bank והכבל של השטח**, טעונים.
- [ ] מחשב (או טלפון עם אפליקציית SSH) באותה רשת Wi-Fi כמו ה-Pi.
- [ ] אנטנת VHF אחת לפחות. שנייה — לא חובה.
- [ ] (לא חובה) מד זרם USB קטן — אם יש לך, הוא יגיד כמה כל מקלט מושך באמת.

**לא לחבר:** את אנטנת ה-SATCOM / ה-LNA. הבדיקה הזו לא צריכה אותם (ה-bias-T כבוי ממילא).

## שלב 1 — חיבורים (5 דקות)

1. **כבה את ה-Pi** אם הוא דולק (מה-UI או `sudo poweroff`), וחכה שהנורה הירוקה תפסיק להבהב.
2. חבר את **ה-RSP1B** לאחד משני שקעי ה-USB **הכחולים**.
3. חבר את **ה-RSP1A** לשקע ה-USB **הכחול השני**.
   > למה כחולים: ב-Pi 5 שני השקעים הכחולים אמורים להיות על שני בקרי USB שונים, כך ששני
   > המקלטים לא חולקים קו. אל תסמוך על זה — הסקריפט מראה את זה בפועל (שלב 4).
4. חבר את אנטנת ה-VHF ל-**RSP1B**. אם יש לך שנייה — ל-RSP1A. אם אין, השאר את ה-RSP1A
   בלי אנטנה. זה לא מזיק למקלט.
5. חבר את ה-Pi ל-**power bank של השטח, עם הכבל של השטח**.
6. חכה כדקה שה-Pi יעלה.

## שלב 2 — להתחבר ל-Pi (5 דקות)

1. פתח טרמינל במחשב (ב-Windows: "Terminal" או "PowerShell").
2. התחבר. במקום `pi` שים את שם המשתמש שאיתו התקנת, ובמקום הכתובת — את ה-IP של ה-Pi
   (אותה כתובת שאתה פותח בדפדפן, בלי `:8080`):

```bash
ssh pi@192.168.1.50
```

3. התקן את `tmux`. הוא שומר על הבדיקה רצה גם אם החיבור מהמחשב נופל באמצע:

```bash
sudo apt install -y tmux
```

4. פתח חלון `tmux` בשם `probe`:

```bash
tmux new -s probe
```

   מעכשיו כל הפקודות רצות בתוך החלון הזה.
   > אם החיבור נופל: התחבר שוב (סעיף 2) והקלד `tmux attach -t probe` — תחזור בדיוק לאן שהיית.

## שלב 3 — להוריד את הסקריפט (דקה)

הסקריפט נמצא עדיין בענף נפרד (לא ב-main). הפקודות האלה מורידות **רק את הקובץ הזה**, בלי
לשנות שום דבר בהתקנה שלך:

```bash
git -C ~/AIR-AM fetch origin claude/trusting-mayer-xclwma
```

```bash
git -C ~/AIR-AM show FETCH_HEAD:scripts/airam-dual-sdr-probe > ~/airam-dual-sdr-probe
```

```bash
chmod +x ~/airam-dual-sdr-probe
```

> אם שכפלת את AIR-AM לתיקייה אחרת מ-`~/AIR-AM`, החלף את הנתיב.
> ⚠ **לא** להריץ `install.sh` בשביל הבדיקה הזו — אין צורך.

## שלב 4 — בדיקת זיהוי (2 דקות, לא משנה כלום)

```bash
sudo ~/airam-dual-sdr-probe --info
```

**מה אתה אמור לראות:**

| שורה בפלט | תקין | אם לא |
|-----------|------|--------|
| `--- USB (1df7 = SDRplay)` | **שתי** שורות `ID 1df7:...` | רק אחת ⇒ מקלט לא מחובר טוב. נתק, חבר מחדש, חכה 10ש', הרץ שוב |
| `--- SDRplay API` | **שני** מקלטים, אחד עם `RSP1A` ואחד עם `RSP1B` | ר' טבלת התקלות למטה |
| `--- טופולוגיה (lsusb -t)` | שני המקלטים תחת `Bus` **שונה** | לא מכשיל — רק תרשום. אם אותו Bus, נסה להחליף שקע |
| `usb_max_current_enable` | `0` (צפוי ב-power bank) | `1` ⇒ ספר לי לפני שממשיכים |
| `get_throttled` | `0x0 (נקי)` | משהו אחר ⇒ ה-power bank כבר מתקשה, **עוד לפני שהתחלנו**. אפשר להמשיך — זה בדיוק מה שנמדד |

**צלם את המסך** (או העתק את הפלט) — זה חלק מהתוצאה.

## שלב 5 — להעביר את AIR-AM ל-standby (דקה)

הסקריפט מסרב לרוץ כשמצב כלשהו פעיל (הוא לא מכבה את AIR-AM בעצמו).

1. פתח בטלפון את דף AIR-AM (`http://<IP>:8080`).
2. לחץ על **🏠** למעלה.
3. בפאנל "מרכז הבקרה" לחץ **⏻ עצור מקלט**.
   > אם הכפתור לא מופיע — AIR-AM כבר ב-standby. מצוין.
4. ודא שכתוב שהמקלט כבוי (standby).

## שלב 6 — הבדיקה המלאה (~22 דקות)

```bash
sudo ~/airam-dual-sdr-probe
```

**מה יקרה:**

1. שוב פלט הזיהוי, ואז:
   ```
   --- ראשי (A): SDRplay Dev1 RSP1B ...
   --- משני (B): SDRplay Dev0 RSP1A ...
   ```
   ודא שה-RSP1B הוא הראשי. אם הפוך — `Ctrl+C`, ושלח לי את פלט שלב 4 (נריץ עם
   `--serial-a`/`--serial-b`).
2. **`=== baseline`** (דקה) — כלום לא רץ. מודד את ה-Pi במנוחה, לבסיס השוואה.
3. **`=== dual-voice-2p`** (10 דקות) — שני המקלטים בקול, תהליך לכל מקלט: מגדל על ה-RSP1B,
   גישה + Control על ה-RSP1A.
   כל 10 שניות תופיע שורה כמו:
   ```
   [run 120ש'] 5V=5.02V throttled=0x0 rtl_airband 18% sdrplay_api 9%
   ```
   - **רוצה לשמוע?** `http://<IP>:8000/airam-probe-a.mp3` (מגדל) או `airam-probe-b.mp3` (גישה).
     לא חובה.
4. **`=== voice-acars`** (10 דקות) — קול על ה-RSP1B, ACARS על ה-RSP1A.
5. **`=== סיכום`** — שורה לכל תרחיש: `✓ עבר` או `✗ נכשל`, עם הסיבה.

**בזמן הבדיקה:**
- **אל תיגע** בכבלים ובמקלטים.
- אל תפתח מצבים ב-UI של AIR-AM.
- אפשר לסגור את המחשב: לחץ `Ctrl+B` ואז `D` (הבדיקה ממשיכה ברקע). כדי לחזור:
  התחבר ב-SSH ו-`tmux attach -t probe`.
- רוצה לעצור באמצע? `Ctrl+C`. הסקריפט מכבה את מה שהריץ ושומר את מה שנמדד עד אז.

**אם ה-Pi נכבה לגמרי באמצע** — **זו תוצאה, לא תקלה שלך.** זה בדיוק מה שהבדיקה מחפשת.
חבר אותו שוב לחשמל, וקפוץ ל"אם ה-Pi נכבה" בשלב 8.

## שלב 7 (לא חובה) — בדיקת ניתוק (~5 דקות)

רק אם שלב 6 עבר. בודק מה קורה למקלט הראשי כשמנתקים את המשני.

```bash
sudo ~/airam-dual-sdr-probe --unplug --only voice-acars --secs 60
```

הסקריפט יבקש ממך, בזמן שהוא רץ:
1. `>>> נתק עכשיו את המקלט המשני (...RSP1A...) ולחץ Enter` ⇐ שלוף את כבל ה-USB של **ה-RSP1A**
   (רק אותו!), ואז Enter.
2. חכה 30 שניות.
3. `>>> חבר אותו בחזרה ולחץ Enter` ⇐ חבר את ה-RSP1A לאותו שקע כחול, ואז Enter.
4. חכה דקה עד הסיכום.

זו תצפית, אין כאן "עבר/נכשל".

## שלב 7ב — מדידת "המפצל": ACARS + VDL2 על המקלט המשני (~6 דקות)

בודק אם הרעיון של `docs/dual-sdr-feasibility.md` §11.3 בכלל אפשרי **על ה-power bank**: הקול
רץ על הראשי, והמשני דוגם בקצב רחב (6.3Msps) — הקצב שמפצל ACARS+VDL2 יצטרך. **אין כאן פענוח**;
זה מודד את המחיר של הקצב עצמו: האם המקלט מקבל אותו, overflow, CPU, ונפילות מתח. המשני עולה
10 שניות אחרי שהקול סיים לעלות — בדיוק כמו במוצר.

לפני: AIR-AM ב-standby (שלב 5), ולהוריד שוב את הסקריפט (שלב 3) — יש בו תרחיש חדש.

```bash
sudo ~/airam-dual-sdr-probe --only baseline,wide-rate --secs 300
```

מה לחפש בסיכום של `wide-rate`:
- **✓ עבר** — אין overflow ואין נפילת מתח: אפשר להתקדם לאב-טיפוס של המפצל.
- **"דחה את הקצב"** — ה-API לא מקבל 6.3Msps. אפשר לנסות קצב אחר שמתאים לשני המפענחים
  (כפולה של 420kHz): `--wide-rate 6.72e6`.
- **overflow** — ה-USB/CPU לא עומדים. נסה את המקלטים על שני השקעים הכחולים (בקרים נפרדים).
- **undervoltage** — ה-power bank לא מחזיק את זה. זו תשובה בפני עצמה.

שלח לי את ה-`summary.json` (שלב 8) — חשוב במיוחד `rate_test` ו-`cpu_proc_pct.sdrplay_api`.

## שלב 8 — לשלוח לי את התוצאות

התוצאות נשמרות בתיקייה `/var/tmp/airam-dual-probe/<תאריך-שעה>/`. הקובץ החשוב: `summary.json`.

**הדרך הקלה** — להציג אותו ולהעתיק:

```bash
cat "$(ls -td /var/tmp/airam-dual-probe/*/ | head -1)summary.json"
```

סמן את כל הטקסט, העתק, והדבק לי בצ'אט. (אם הוא ארוך מדי — הדבק את מה שמופיע מ-`=== סיכום`
ומעלה עד `=== baseline`, יחד עם הפלט של שלב 4.)

**או** — להעתיק את הקובץ למחשב (מטרמינל **חדש** במחשב, לא בתוך ה-SSH):

```bash
scp -r pi@192.168.1.50:/var/tmp/airam-dual-probe ./airam-dual-probe
```

ולהעלות לי את `summary.json` מהתיקייה שנוצרה.

### אם ה-Pi נכבה באמצע

אין `summary.json`, אבל הדגימות נשמרו עד הרגע האחרון. אחרי שה-Pi עלה שוב, התחבר ב-SSH:

```bash
tail -n 40 "$(ls -td /var/tmp/airam-dual-probe/*/ | head -1)samples.jsonl"
```

שלח לי את הפלט, ותגיד באיזה תרחיש זה קרה (`dual-voice-2p` / `voice-acars`) ואחרי כמה זמן.

## שלב 9 — חזרה לשגרה

1. ב-UI של AIR-AM בחר מצב כרגיל (📻 קול וכו'). המקלט הראשי ממשיך לעבוד כמו תמיד.
2. את ה-RSP1A אפשר להשאיר מחובר או לנתק — כרגע AIR-AM לא משתמש בו.
   > ⚠ עם שני מקלטים מחוברים, AIR-AM של היום עלול לפתוח את **ה-RSP1A במקום ה-RSP1B**
   > (זה בדיוק אחד הממצאים במסמך ההיתכנות, §3.1). **עד שזה יתוקן — נתק את ה-RSP1A
   > אחרי הבדיקה.**
3. לסגור את `tmux`: הקלד `exit`.

## הרצה שנייה (לא חובה): השוואה מול ספק רשמי

אם שלב 6 **נכשל** על ה-power bank, ויש לך ספק רשמי 5V/5A (27W) — הרצה נוספת עליו תגיד
אם הבעיה היא הספק או ה-Pi עצמו. כבה את ה-Pi, העבר לספק הרשמי, ואז שלבים 2, 5 ו-6 שוב
(הפעם `--secs 300` מספיק). שלח את שתי התוצאות.
