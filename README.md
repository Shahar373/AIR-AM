# AIR-AM ✈️ — האזנה לתדרי תעופה דרך הטלפון

האזנה לתדרי תעופה (Air band, AM, 118–137 MHz) באמצעות **Raspberry Pi 5 + SDRplay RSP1B**,
עם **ממשק וובי לבחירת תדר** (פריסטים + תדר חופשי) שנפתח מכל טלפון — בלי אפליקציה ייעודית
ובלי סיסמאות.

```
  אנטנה ──► SDRplay RSP1B ──► Raspberry Pi 5
                                  │  SDRplay API + SoapySDR + SoapySDRPlay3
                                  ▼
        ┌────────────────┐   כותב conf + restart   ┌──────────────┐
        │  airam-web     │ ───────────────────────►│ rtl_airband  │
        │ (בורר תדרים)   │◄─── בחירת תדר ───────────│ (פענוח AM)   │
        │   :8080        │      מהטלפון              └──────┬───────┘
        └────────────────┘                                 │ סטרים MP3
                                                            ▼
                                                     Icecast2 :8000
                                                            │
                                                   הטלפון (דפדפן / נגן)
```

הטלפון פותח דף אחד (`http://<IP>:8080`), בוחר פריסט או מקליד תדר — וזהו.

## מטרות הפרויקט ומהותו 🎯

AIR-AM הופך **Raspberry Pi 5 + SDRplay RSP1B** לתחנת האזנה לתעופה שנשלטת **כולה
מהטלפון בדפדפן**. עקרונות המנחים:

- **שליטה מלאה מהטלפון** — דף ווב אחד הוא משטח הבקרה היחיד (תדר, מצב, gain, squelch,
  יומן, מפה, מדדים). בלי אפליקציה ייעודית, בלי סיסמאות.
- **אפס-קונפיגורציה** — מתקין-על אחד (`install.sh`) עושה הכול אוטומטית, ואידמפוטנטי
  (`git pull && sudo ./install.sh`).
- **headless ועמיד** — השירותים עולים באתחול, מתאוששים מניתוק USB/קריסה, **והמצב
  שבחרת (קול/ACARS/VDL2/כיבוי) שורד reboot** — התחנה קמה איפה שהשארת אותה.
  **הרדיו אינו תלוי באינטרנט** — תקלת רשת לא נוגעת בנתיב האודיו.
- **פרטיות ומקומיות** — הכול רץ על ה-Pi (פענוח, הקלטות, תמלול, ניתוח ADS-B). בלי ענן.
  מיועד **לרשת פרטית מהימנה בלבד**.

**מה זה עושה:** (1) **מצב קול 📻** — בורר תדרי Air band (AM, 118–137 MHz) עם הקלטות,
תמלול ATC, ומדדי RF חיים. (2) **מצב ACARS 📡** — פענוח הודעות נתונים של מטוסים עם מפה.
(3) **מודעוּת מרחבית** — הסקת המסלול הפעיל בנתב"ג ואינדיקציית שיבוש GPS מנתוני ADS-B.

> 🛠️ **מפתחים:** הארכיטקטורה המלאה, מפת הקוד, מודל האבטחה ומדריך הוספת פיצ'ר/תיקון
> באג נמצאים ב-[`CLAUDE.md`](CLAUDE.md). היסטוריית הגרסאות ב-[`CHANGELOG.md`](CHANGELOG.md).

## למה לא פשוט SDRConnect?

ל-**SDRConnect אין אפליקציית לקוח לטלפון**. מצב ה-"Audio" שלו דורש לקוח דסקטופ (Windows/Mac/Linux),
אז אי אפשר פשוט לפתוח בטלפון ולהאזין. **RTLSDR-Airband + Icecast** בנוי בדיוק למטרה הזו, רץ headless,
ותומך ב-RSP1B דרך **SoapySDR** (`driver=sdrplay`) — השם "RTLSDR" היסטורי בלבד.

## דרישות

- **חומרה:** Raspberry Pi 5 (או 4), SDRplay RSP1B, אנטנה ל-VHF (~120 MHz).
- **מערכת:** Raspberry Pi OS 64-bit (Bookworm).
- **רשת:** הטלפון וה-Pi באותה רשת מקומית.
- **אופציונלי (למצב SATCOM 📶):** אנטנת **L-band** (‎~1.5GHz, RHCP) + **LNA** (למשל
  Nooelec SAWbird+ IO), מוחלפת ידנית במקום אנטנת ה-VHF. ראה [מצב SATCOM 📶](#מצב-satcom-)
  ו-[`docs/satcom-feasibility.md`](docs/satcom-feasibility.md).

## התקנה (פקודה אחת)

הרץ **על ה-Pi**:

```bash
git clone https://github.com/Shahar373/AIR-AM.git
cd AIR-AM
chmod +x install.sh
sudo ./install.sh
```

הסקריפט עושה **הכל אוטומטית**:
1. תלויות מערכת (כולל Python/Flask).
2. **SDRplay API** — מוריד את ה-`.run`, מחלץ אותו ומתקין את הספרייה והשירות (ללא אישור רישיון ידני).
3. בונה `SoapySDRPlay3` ו-`rtl_airband`.
4. מגדיר `Icecast2` — **מאזינים ללא סיסמה** (סיסמת ה-source פנימית וקבועה, לא נחשפת).
5. מתקין את שרת בורר התדרים ואת שירותי ה-systemd. באתחול עולים `sdrplay` ו-`airam-web`
   (המתזמר), ו-`airam-web` מפעיל את מצב ההאזנה השמור האחרון (קול/ACARS/VDL2/כיבוי).

בסיום תקבל כתובת: `http://<IP-של-ה-Pi>:8080`

> אם SDRplay יוציאו גרסת API חדשה והקישור ישתנה — עדכן את `SDRPLAY_VER` בראש `install.sh`.

### עדכון גרסה (Pi שכבר מותקן)

```bash
cd ~/AIR-AM
git pull
sudo ./install.sh
```

ההתקנה אידמפוטנטית: מדלגת על מה שכבר מותקן, בונה מחדש את `rtl_airband` רק כשצריך
(ייקח כמה דקות), ובסוף **מפעילה מחדש את כל השירותים** כך שהבינארי, הקוד וההגדרות
החדשים נקלטים מיד — בלי reboot.

> **מספר הגרסה מוצג בראש הממשק** (למשל `v1.0.0 · SDRplay RSP1B`) — כך אפשר לוודא
> שה-Pi קלט את העדכון. הגרסאות מתויגות ב-git (`vX.Y.Z`, ראה `CHANGELOG.md`).

## HTTPS והתקנה כאפליקציה (PWA) 🔒📱

ב-HTTP אפשר להאזין מהדפדפן, אבל **התקנה מלאה כאפליקציה (PWA) ו-Service Worker
דורשים HTTPS**. הדרך הפשוטה והמומלצת — אתה כבר על **Tailscale** — היא
`tailscale serve`, שנותן תעודת HTTPS אמיתית ומהימנה (Let's Encrypt) על שם
ה-MagicDNS של ה-Pi, בלי אזהרות ובלי להתקין CA:

```bash
# פעם אחת בלוח הבקרה של Tailscale: להפעיל MagicDNS + HTTPS Certificates.
# ואז על ה-Pi:
sudo tailscale serve --bg 8080
tailscale serve status        # יציג את כתובת ה-https://<machine>.<tailnet>.ts.net
```

מעכשיו נכנסים מהטלפון ל-**`https://<machine>.<tailnet>.ts.net`** (במקום `IP:8080`),
ואפשר "הוסף למסך הבית" → האפליקציה נפתחת במסך מלא.

> **למה זה נדרש לשמע:** בדף HTTPS הדפדפן חוסם סטרים HTTP ישיר מ-Icecast
> (mixed-content). לכן כשהדף מוגש ב-HTTPS, נגן הדפדפן עובר אוטומטית ל-proxy
> same-origin (`/stream`) שמגיש את אותו סטרים דרך שרת הווב. ב-HTTP/LAN הנגן
> ממשיך לגשת ל-Icecast ישירות (latency נמוך יותר). אין צורך בהגדרה — זה אוטומטי.

> גישה מ-LAN בלבד (בלי Tailscale) תישאר HTTP. להתקנת PWA מ-LAN צריך תעודה
> מהימנה (למשל `mkcert` עם CA שמותקן בטלפון) — מעבר לתחום של הקובץ הזה.

## שימוש — בורר התדרים 🎛️

פתח בטלפון: **`http://<IP-של-ה-Pi>:8080`**

- **פריסטים:** כפתורים מהירים לתדרי נתב"ג (מגדל, ATIS, גישה, קרקע וכו').
  כפתור **✎ עריכה** מאפשר להוסיף ולמחוק פריסטים ישירות מהממשק (נשמרים ב-Pi).
- **תדר חופשי:** הקלד כל תדר (למשל `134.600`) ולחץ "כוונן".
- **אפנון:** AM (תעופה) או NFM.
- **בקרת רווח (Gain):** ברירת מחדל **IF AGC** אוטומטי (מומלץ). כיבוי ה-AGC חושף שני
  סליידרים בסגנון SDRplay — **IF Gain** (רווח תדר-הביניים) ו-**RF Gain** (מצב ה-LNA),
  עם תצוגת **System Gain** משוערת. חיווי **"עומס יתר"** נדלק כשהאות מתקרב לרוויה (הורד רווח).
- **סקוולץ׳ (Squelch):** שלושה מצבים —
  **אוטומטי** (ברירת מחדל, פותח ~9.54dB מעל הרעש, מתאים לרוב התדרים) ·
  **תמיד פתוח** (חובה ל-ATIS ושידור רציף — שם ה-auto נכשל כי אין שקט לכיול) ·
  **ידני** עם סף SNR ב-dB — מקלידים ערך מדויק (או גוררים סליידר, 0–60 dB) וה-SNR
  החי מוצג לידו כעוגן לבחירה. בחירת הפריסט **ATIS** עוברת אוטומטית ל"תמיד פתוח".

בכל בחירה השרת כותב הגדרות חדשות ומפעיל מחדש את `rtl_airband` (~3 שניות), והנגן מתחבר מחדש לבד.
זה כמו חוגת רדיו: **תדר אחד פעיל בכל רגע** (יש לך RSP1B אחד).

- **נגן מותאם 🎵:** כפתור ▶ עגול גדול במקום נגן הדפדפן — לחיצה תמיד מסנכרנת
  ל-live (ברדיו חי אין "המשך מאיפה שעצרת"), עם סליידר עוצמת שמע שנשמר בדפדפן
  (מוסתר ב-iOS, שם העוצמה נשלטת רק בכפתורי החומרה).

- **מדדי RF חיים:** מתחת לנגן מוצגים **SNR** (אות-מינוס-רעש ב-dB), עוצמת אות ורצפת רעש
  (dBFS) וגרף SNR של הדקות האחרונות. הנתונים מגיעים מ-`rtl_airband` עצמו
  (`stats_filepath`) ומתרעננים כל ~1 שנייה — משוב כמעט-רציף לכיוון אנטנה ול-Gain:
  סובב/הזז את האנטנה וראה את ה-SNR משתפר בזמן אמת.

- **חיווי מתח ל-Pi 🔋:** מתחת לנגן מוצג מצב אספקת המתח (`vcgencmd`) — ירוק=תקין,
  כתום=המתח צנח בעבר, אדום=מתח נמוך עכשיו. **קריטי בהזנה מסוללה ניידת:** סוללה
  חלשה גורמת ל-undervoltage שמשבש את ה-SDR. ב-Pi 5 מוצג גם מתח הכניסה (5V) והטמפ'.

- **התקנה כאפליקציה ושמע ברקע 📱:** האתר הוא **PWA** — ב-Android (Chrome: ⋮ → "הוסף
  למסך הבית") או iPhone (Safari: שיתוף → "הוסף למסך הבית") הוא נפתח כאפליקציה במסך
  מלא. באמצעות **MediaSession** ההאזנה ממשיכה ברקע (יציאה מהאפליקציה / מסך נעול) עם
  פקדי ניגון/עצירה במסך הנעול. אין בדפדפן API ל"שיחת טלפון"; MediaSession הוא
  המנגנון הסטנדרטי לשמע רקע וזה מה שמשמש כאן.

- **יומן שידורים + הקלטות 🎙️:** כל פתיחת סקוולץ' מוקלטת אוטומטית ל-MP3 נפרד,
  והכרטיס "יומן שידורים" מציג מה קרה ומתי — עם כפתור ▶ לשמיעה חוזרת של כל שידור.
  נשמרים ~200 השידורים האחרונים (עד ‎100MB, נמחקים מהישן). במצב סקוולץ'
  "תמיד פתוח" (ATIS) אין הקלטה — אין שם שידורים בדידים.

- **תמלול ATC (אופציונלי) 📝:** כל שידור מוקלט מתומלל מקומית על ה-Pi
  (`whisper.cpp`, מודל `base.en` — אנגלית), והטקסט מוצג מתחת לשידור ביומן וניתן
  לחיפוש. הכל אופליין ופרטי, בלי ענן. **כבוי כברירת מחדל** (צריכת CPU/בנייה ארוכה);
  הפעלה: `INSTALL_WHISPER=1 sudo ./install.sh`. לכיבוי — הסר `AIRAM_TRANSCRIBE`
  מ-`/etc/airam/airam.env` והרץ `sudo systemctl restart airam-web`.
  > הערה: שמע ATC רועש ומהיר — הדיוק טוב לכיווּן/חיפוש כללי, לא מושלם מילה-במילה.
  > לדיוק גבוה יותר אפשר מודל גדול יותר (`AIRAM_WHISPER_MODEL`).

- **METAR נתב"ג 🌤️:** כשיש ל-Pi אינטרנט מוצג מזג האוויר העדכני של LLBG
  (רוח, ראות, טמפרטורה, QNH) — נוח לצד האזנה ל-ATIS.

> בדיקה ראשונה: בחר **ATIS 132.5** — הוא משדר ברצף, אז אם נשמע משהו, כל השרשרת עובדת.

## מצבי ההפעלה — מרכז / קול / ACARS / VDL2 / SATCOM / סריקה 🏠📻📡🛰️📶🔁

בראש הממשק יש מתג תצוגות: **🏠 מרכז** / **📻 קול** / **📡 ACARS** / **🛰️ VDL2** /
**📶 SATCOM**, ולצידו כפתור **⏻ כיבוי**. **אין "מצב ראשי"** — כל המצבים שווי-מעמד,
וכל אחד מופעל ונעצר בפני עצמו:

- **🏠 מרכז (מסך הבית)**: הנחיתה הניטרלית — סטטוס חי של המקלט, חמישה כרטיסי הפעלה
  (עם התדר/הבנק/הלוויין השמורים של כל מצב), פאנל המסלולים הפעילים בנתב"ג, ה-METAR,
  ופאנל **רוסטר מטוסים מאוחד** (ACARS+VDL2+SATCOM+ADS-B, ר' בהמשך). זו גם התצוגה של
  מצב הכיבוי (Standby) ושל מצב הסריקה.
- **📻 קול**: בורר התדרים — האזנה ל-AM/NFM (מגדל, ATIS, גישה…), מדדי RF, יומן והקלטות.
- **📡 ACARS**: פענוח **הודעות ACARS** (תקשורת נתונים דיגיטלית של מטוסים — מספר זנב,
  מספר טיסה, הודעות תפעוליות) בהצגה חיה.
- **🛰️ VDL2**: פענוח **VHF Data Link Mode 2** (הדור הבא — כולל CPDLC/ADS-C שלא רצים
  על ACARS VHF). ראה הפרק [מצב VDL2 🛰️](#מצב-vdl2-) בהמשך.
- **📶 SATCOM**: פענוח **ACARS דרך לוויין Inmarsat** (L-band, ‎~1.5GHz) — התעבורה
  של מטוסים מעל אוקיינוסים/אזורים בלי כיסוי VHF. ⚠ דורש אנטנת L-band נפרדת (החלפה
  ידנית). ראה הפרק [מצב SATCOM 📶](#מצב-satcom-) בהמשך.
- **🔁 סריקה**: מחזור אוטומטי בין המצבים לפי לוח זמנים שאתה בונה בכרטיס "סריקה"
  במסך הבית — למשל 📻 קול דקה, 📡 ACARS דקתיים, 🛰️ VDL2 דקתיים, וחוזר חלילה. הכרטיס
  מציג את הרגל הנוכחית וספירה-לאחור למעבר הבא. כשל ברגל בודדת מדלג לרגל הבאה
  (לא עוצר את הסריקה); רק כשל של *כל* הרגלים ברצף עובר לכיבוי. אפשר גם להגביל
  רגל **לחלון שעות** (למשל ACARS פעיל רק 06:00–22:00) — שני שדות שעה אופציונליים
  בעורך הלוח, ריק = פעילה תמיד. רגל מחוץ לחלון שלה מדולגת בשקט; אם אף רגל לא
  בחלון כרגע, המקלט פשוט ממתין (לא נחשב תקלה).
- **⏻ כיבוי (Standby)**: עוצר את המקלט לגמרי (קול, ACARS, VDL2, SATCOM והסריקה)
  **ומשחרר את ה-RSP1B ליישום SDR אחר** — בעוד דף הבקרה נשאר פעיל. שירות ה-SDRplay
  API נשאר חי כדי שאפליקציית SDR אחרת תוכל להתחבר מיד. **▶ הפעלה** מחזירה את המצב
  האחרון שהיה פעיל.

**המצב שורד reboot**: התחנה קמה באתחול במצב שבו השארת אותה — קול, ACARS, VDL2,
SATCOM ואפילו כיבוי. שרת הווב (airam-web) הוא "המתזמר": הוא קורא את המצב השמור באתחול
ומפעיל את השירות המתאים. כישלון בהפעלת מצב (למשל SDR תקול) מוריד את המערכת
ל-Standby עם הודעת שגיאה במסך הבית — אף פעם לא "בורח" למצב אחר בשקט.

### חשוב — מקלט אחד, בהחלפה

ל-RSP1B יכול לגשת **תהליך אחד בלבד** בכל רגע. `rtl_airband` מפענח **קול**, `acarsdec`
מפענח **ACARS**, ו-`dumpvdl2` מפענח **VDL2** — שלושה תהליכים נפרדים המתחרים על אותו מקלט.
לכן **אי אפשר להריץ שניים מהם בו-זמנית עם SDR אחד**: מעבר לכל מצב עוצר את השניים האחרים.
המעבר מהיר (~3 שניות), ושירותי systemd מוגדרים `Conflicts` כך שלעולם לא ירוצו יחד על המכשיר.

> רוצה **בו-זמני אמיתי** (לשמוע מגדל *וגם* לראות ACARS במקביל)? הוסף **דונגל RTL-SDR שני**
> זול — אז ה-RSP1B נשאר על הקול וה-RTL-SDR מריץ ACARS. זה דורש שינוי קונפיגורציה
> (לא נכלל כרגע); המימוש הנוכחי הוא החלפה עם מקלט אחד.

### שימוש

1. לחץ **📡 ACARS** למעלה — ה-Pi מפעיל את `acarsdec` על תדרי ה-ACARS.
2. ההודעות מופיעות בדף ככל שמתפענחות, בכרטיס **אחיד לכל הפורמטים**: קטגוריה קריאה
   (label / CPDLC / ADS-C), badge צבעוני, זמן, תדר, זנב, טיסה וטקסט. פענוח ARINC-622
   (דרך `libacars`) מוצג בולט, והגולמי מתקפל מתחתיו. כמה labels נפוצים מפוענחים בנוסף
   לתצוגה קריאה: **Loadsheet אלקטרוני** (משקל המראה/נוסעים, label C1), **PDC — אישור
   טרום-המראה** (יעד/מסלול/SID/סקוואק/תדר הבא, label A3), ודיווחי מיקום ממספר פורמטים.
3. כדי לחזור לשמע — לחץ **🎧 האזן למגדל (134.600)** או החלף בחזרה ל-**📻 קול** למעלה.

> **ACARS משדר בבזקים קצרים**, לא ברצף — ייתכנו דקות של שקט בין הודעות. זה תקין.
> לבדיקה ראשונה, השאר את המצב פעיל כמה דקות סמוך לתנועה אווירית.

### שמירה, ייצוא ומפה

- **שמירה**: כל הודעה נשמרת ל-`/var/lib/airam/acars.jsonl` ו**שורדת אתחול**.
- **תצוגת "היום בלבד"**: הפיד מציג כברירת מחדל רק את ההודעות שנקלטו **היום** (שעון ה-Pi),
  כך שסשן חדש ליד השדה לא מוצף בתעבורת ימים קודמים. ההיסטוריה המלאה **אינה נמחקת** —
  היא נשמרת בדיסק וזמינה בייצוא CSV/JSON (וגם דרך `GET /api/acars?all=1`).
- **ארכיון חיפוש רב-יומי**: בורר התאריך שמעל תיבת החיפוש פותח כל יום קודם שנשמר
  (עד לגבול השמירה, כ-5000 הודעות אחרונות) — עם אותם חיפוש, סינון, roster ומפה
  כמו בשידור החי. כפתור **◀ חזרה לשידור חי** חוזר לפיד המתעדכן. עובד בדיוק אותו
  דבר גם בתצוגת VDL2.
- **ייצוא** לניתוח offline: כפתורי **⬇ CSV / JSON** (או `GET /api/acars/export?format=csv|json`).
  ה-CSV כולל BOM כך ש-Excel מציג עברית נכון.
- **מדדי איכות קליטה**: כל כרטיס מציג **dBFS** (עוצמת האות הגולמית מהמפענח). כרטיסי
  **VDL2** מציגים גם **SNR** אמיתי (ה-dumpvdl2 מודד רצפת רעש לכל הודעה); כרטיסי ACARS
  מציגים dBFS בלבד — ל-acarsdec אין מדידת רצפת-רעש, ולכן לא מוצג SNR מוערך/מומצא.
- **רוסטר מטוסים מאוחד** (במסך הבית 🏠): כל מטוס שנקלט ב-ACARS **או** ב-VDL2 מופיע
  ברשימה אחת, עם תגית מקור (📡/🛰️) לכל ערוץ שזיהה אותו וסימון 🛰 אם הוא משדר ADS-B
  כרגע. שימושי לראות בבת אחת מי "באוויר" בלי לעבור בין התצוגות — ומתעדכן גם
  כשהמקלט ב-Standby (הנתונים כבר בזיכרון מהיסטוריית ההודעות + ADS-B).
- **מפה** (Leaflet + OpenStreetMap): מטוסים עם **מיקום** מ-ACARS — ADS-C, ודיווחי מיקום
  מפוענחים ממספר פורמטים (`/.POS/`, label 15, label 16 עשרוני, דוח ניווט/דלק 1L, וטקסט
  חופשי heuristic). chip **📍** בכרטיס ממקד את המטוס במפה. המפה מציירת
  **שובל מסלול** (קו) המחבר מיקומים עוקבים של אותו זנב — נתיב הטיסה, לא רק הנקודה האחרונה.
  אם אין אינטרנט בטלפון, המפה נופלת חיננית והמיקומים נשארים זמינים כ-📍 בכרטיסים.
- **מיקוד למטוס (drill-down)**: לחיצה על **זנב/טיסה** (בכרטיס או ב-popup של המפה) מסננת
  את הפיד למטוס הזה בלבד וממקדת את המפה על המסלול שלו; צ'יפ "מטוס: … ✕" מנקה את המיקוד.
- **חיפוש וסינון**: תיבת חיפוש (זנב/טיסה/label/טקסט) + צ'יפים לסינון לפי קטגוריה,
  עם שורת סטטיסטיקה (הודעות · הודעות/דק׳ · מטוסים · עם מיקום · 🛰 ב-ADS-B).
- **העשרת ADS-B 🛰**: מטוס מה-ACARS שמשדר כרגע גם ADS-B (לפי נתוני adsb.lol שכבר
  נמשכים עבור זיהוי המסלול הפעיל) מקבל badge **🛰** ברשימת המטוסים, **סוג מטוס
  סמכותי** (במקום ניחוש מהטקסט), ובפאנל הפירוט: callsign, גובה, מהירות וכיוון חיים +
  **שובל ADS-B חי** (קו מקווקו) במפה לצד נקודות ה-ACARS. באזור שיבוש GPS (כרוני
  בנתב"ג) נ"צ מזויף **מדוכא** ומוצגת התראת "GPS משובש ⚠" — הגובה והמהירות נשארים
  אמינים. אין אינטרנט? ההעשרה פשוט לא מוצגת — הקליטה עצמה לא תלויה ברשת.

### תדרי ACARS — בנקים

בכותרת מצב ה-ACARS יש **בורר בנקים**. כל בנק הוא קבוצת תדרים ש**נכנסת בחלון דגימה אחד**
של ה-SDR (acarsdec מפענח עד **8 ערוצים** בתוך חלון של כ-**2 MHz**). שני בנקים מובנים:

| בנק | תדרים (MHz) | מה נתפס |
|-----|-------------|---------|
| **אירופה + עולמי (131)** (ברירת מחדל) | 130.450 · 131.425 · 131.525 · 131.550 · 131.725 · 131.825 · 131.850 | צביר אירופה/SITA + הראשי העולמי **131.550** (גם מטוסי **תדלוק/צבא אמריקאים**) |
| **אזור 136** | 136.700 · 136.750 · 136.800 · 136.850 · 136.900 · 136.925 · 136.975 | ערוצי SITA/ARINC ב-136 MHz |

> **למה בנקים ולא הכול ביחד?** צביר 131.x וצביר 136.x רחוקים זה מזה כ-5 MHz — הרבה מעבר
> לחלון דגימה אחד. לכן בוחרים בנק אחד בכל פעם (החלפה ~3 שניות, כמו מתג קול/ACARS).
> **מטוסי תדלוק וצבא אמריקאים אינם משתמשים בתדר ACARS צבאי נפרד** — הם על רשת ARINC/SITA
> האזרחית, ובפועל מופיעים על **131.550** (שכלול בבנק ברירת המחדל).

בחירת בנק בזמן קליטה חיה מחליפה מיד את החלון. לשינוי **ברירת מחדל קבועה** ערוך את
`config/acars.env` בריפו (או את `ACARS_BANKS` ב-`webtune/app.py`). עריכה ידנית של
`/etc/airam/acars.env` אפשרית (פורמט EnvironmentFile של systemd), אך **כל מעבר ל-ACARS
מהממשק דורס אותה**:

```bash
ACARS_FREQS=130.450 131.425 131.525 131.550 131.725 131.825 131.850   # MHz, מופרדים ברווח
ACARS_GAIN=-10                                 # -10 => AGC; אחרת dB ידני
ACARS_RATEMULT=160                             # 160 => 2.0 MS/s, 192 => 2.4 MS/s
```

> **אבטחה:** `airam-web` רץ כ-non-root; המעבר בין המצבים עובר דרך sudoers ממוקד שמתיר
> *רק* את פקודות ה-systemctl המדויקות הדרושות. קובץ ה-`acars.env` מנותח ע"י systemd
> (לא shell) => אין הסלמת הרשאות מ-airam ל-root.

## מצב VDL2 🛰️

לצד 📻 קול ו-📡 ACARS יש מצב שלישי — **🛰️ VDL2** (VHF Data Link Mode 2). זהו הדור
הבא של תקשורת הנתונים בין מטוסים לקרקע: מודולציה מהירה (D8PSK, 31.5kbps לעומת 2.4kbps
ב-ACARS הקלאסי) על צביר תדרים ב-**136–137 MHz**, כשה**ערוץ העולמי הראשי הוא 136.975
MHz** (Common Signalling Channel). ה-Pi מפענח אותו עם **dumpvdl2** על אותו RSP1B.

**מה נתפס:**
- **ACARS-over-VDL2** — רוב התעבורה. אלה בדיוק אותן הודעות ACARS (ATIS, OOOI, PDC,
  loadsheet, דיווחי מיקום…), ולכן הן מקבלות את **אותו פענוח מלא** כמו במצב ACARS —
  כרטיסים עם קטגוריה, כיוון, מיקום על המפה ו-roster מטוסים.
- **CPDLC / ADS-C / XID** — תעבורת ה-ATN וניהול הרשת שרצה על VDL2 (ולא על ACARS
  VHF!). מוצגת ככרטיס בסיסי עם תקציר מפוענח (טקסט ה-clearance ב-CPDLC, מיקום ב-ADS-C).
  גם מטוס בלי רישום מזוהה לפי כתובת ה-**ICAO** של שכבת ה-AVLC.

**שימוש:** לחץ **🛰️ VDL2** למעלה → **▶ הפעל קליטת VDL2 חיה**. ה-Pi עובר לפענוח (השמע
נעצר — מקלט אחד בהחלפה, כמו ACARS). בכותרת יש **בורר בנקים**: ברירת המחדל *עולמי +
אירופה* (136.725/775/825/875/975) נכנסת כולה בחלון דגימה אחד; בנק *CSC בלבד* (136.975)
מקל על ה-CPU. חזרה לשמע — **🎧 האזן למגדל** או החלף חזרה ל-**📻 קול**.

**שמירה וייצוא:** ההודעות נשמרות ל-`/var/lib/airam/vdl2.jsonl` (שורד restart), וניתן
לייצא הכול מכפתורי **CSV/JSON** (CSV עם BOM ל-Excel, כולל עמודת `icao`).

> **מדוע VDL2 נפרד מ-ACARS?** ב-CHANGELOG (1.10.0) גילינו ש-CPDLC *אינו* מופיע על
> ACARS VHF 131.x באזורנו — חברות התעופה מריצות אותו על VDL2. מצב זה סוגר את הפער.

## מצב SATCOM 📶

מצב רביעי — **📶 SATCOM** — קולט **ACARS דרך לוויין Inmarsat** ב-**L-band (‎~1.5GHz)**.
זו התעבורה של מטוסים **מעל אוקיינוסים ואזורים בלי כיסוי VHF** (שם אין תחנות קרקע):
במקום לשדר ל-ACARS/VDL2 יבשתי, המטוס משדר ללוויין גאו-סטציונרי. ה-Pi מפענח אותו
עם **[`inmarsat-sniffer`](https://github.com/alphafox02/inmarsat-sniffer)** על אותו
RSP1B. הפלט הוא ACARS — ולכן הוא מקבל את **אותו פענוח מלא** (קטגוריות, כיוון, מיקום
על המפה, roster, ארכיון, ייצוא) כמו מצבי ACARS/VDL2.

### ⚠ נדרשת אנטנת L-band (החלפה ידנית)

זה ההבדל המהותי משאר המצבים: אנטנת ה-VHF של התעופה **לא** קולטת L-band. לפני מעבר
למצב SATCOM צריך **פיזית להחליף** את האנטנה. ה-UI מציג באנר-הוראה ותזכורת בעצירה.

| רכיב | פירוט |
|------|-------|
| אנטנה | patch או helix, **RHCP** (קיטוב מעגלי ימני), ל-‎~1545 MHz |
| **LNA (חובה)** | Nooelec **SAWbird+ IO** (‎1.542GHz, ‎~30dB) — צמוד לאנטנה |
| הזנת LNA | ה-**bias-T** של ה-RSP1B (‎+4.7V, מוגבל ל-100mA) — נדלק אוטומטית *רק* במצב SATCOM. **אפשר גם מקור חיצוני** (ראה אזהרת ספק כוח למטה) |
| כבל | RG-400 / LMR-240 (לא RG-58 — מפסידני מדי ב-1.5GHz) |

**כיוון (מישראל):** הלוויין המומלץ הוא **Alphasat** (‎`AF1`, 25°E) — מכוונים את
האנטנה בערך ל-**‎50° מעל האופק, דרום-דרום-מערב**, לשמיים פתוחים. גאו-סטציונרי =
מכוונים **פעם אחת**. פירוט מלא (BOM, חישוב הכיוון, בחירת לוויין) ב-
[`docs/satcom-feasibility.md`](docs/satcom-feasibility.md).

**שימוש:** החלף את האנטנה ל-L-band → לחץ **📶 SATCOM** למעלה → בחר לוויין בבורר
(ברירת מחדל Alphasat) → **▶ הפעל קליטת SATCOM חיה** → אשר בדיאלוג שהאנטנה הוחלפה
(מופיע *לפני* שה-bias-T נדלק בפועל). ה-Pi עובר לפענוח לווייני (השמע נעצר — מקלט
אחד בהחלפה). כשמסיימים — **⏹ עצור**, והחזר את אנטנת ה-VHF.

**🎯 כיוון מדויק: פאנל Eb/No.** אחרי ההפעלה, תצוגת SATCOM מציגה פאנל כיוון קבוע
(לא נעלם ב-standby כמו שאר הפקדים): **Eb/No מיטבי** (המספר שמכווננים לפיו — ככל
שגבוה יותר, טוב יותר) עם גרף היסטוריה שמראה אם הסיבוב האחרון של האנטנה שיפר או
הרע את הקליטה, ופירוט לכל ערוץ (קצב, נעילה, Eb/No, מספר הודעות, גיל). הצביעה
(ירוק/אפור) לפי **נעילה בפועל** של הדמודולטור, לא לפי "ניחוש" מספרי — כי אין
סף Eb/No מוסמך שמגדיר "מספיק טוב" ללא נעילה בפועל. אם ערוץ מציג "—" במקום מספר
— זה אומר שהדמודולטור עדיין לא נעל שם כלל (לא 0dB אמיתי). **טכניקת כיוון:** סובב
לאט את האנטנה תוך מעקב אחר הגרף (מתעדכן כל שנייה); כשמספר הערוצים הנעולים
("נעולים X/Y" בכותרת הפאנל) עולה או שה-Eb/No המיטבי מפסיק לטפס — עצרת במקום
הטוב ביותר. אם שום ערוץ לא נועל אחרי כמה דקות של סיבוב — בדוק חיבור LNA/bias-T
וכיוון גס (‎~50° אלווציה, דרום-דרום-מערב מישראל) לפני שממשיכים לכוונן עדין.

**⚡ מצב חסכון CPU (דלוק כברירת מחדל).** Alphasat מגדיר 12 ערוצים, ומהם **6 הם
C-channels** שנושאים בעיקר קול/דאטה ו**כמעט לא ACARS** — בעוד שהם הדמודולטורים
היקרים ביותר. לפי התיעוד של `inmarsat-sniffer` עצמו, דילוג עליהם חוסך **‎~50%
CPU**. מכיוון ש-AIR-AM קולט ACARS בלבד, זה חיסכון כמעט חינם — ולכן הוא **דולק
כברירת מחדל**. אפשר לכבות אותו במתג "⚡ מצב חסכון CPU" בתצוגת SATCOM אם אתה
רוצה את כל 12 הערוצים (למשל לניסויים). **זה קו ההגנה העיקרי על תקציב החשמל
בהפעלה מסוללה** — ר' האזהרה הבאה.

**⚠ אזהרת ספק כוח:** ה-Pi 5 דורש **5V/5A (25W)** רשמית. bias-T (עד 100mA)
נראה קטן בפני עצמו, אבל בו-בזמן שהוא נדלק גם `inmarsat-sniffer` עולה ומתחיל
עומס CPU — הצירוף עלול לדחוף ספק שולי (במיוחד **power bank נייד**: רבים
מהם, גם כאלה עם USB-C PD, נותנים **5V/3A בלבד** — הפרופילים החזקים יותר
שלהם הם ב-9V/12V, שה-Pi 5 לא משתמש בהם בכלל) **מעבר לתקרה, וגורם לכיבוי
מלא** (לא reboot רך — כיבוי שדורש ניתוק/חיבור פיזי). **הדף מזהיר על כך
בעצמו:** אם `vcgencmd` מדווח שהמתח כבר צנח, דיאלוג האישור לפני כניסה ל-SATCOM
מציג אזהרה מפורשת (בלי לחסום — ההחלטה נשארת שלך), ותצוגת SATCOM מציעה בנקישה
אחת לסמן **"🔌 הזנת LNA חיצונית (bias-T כבוי)"** ל*הזין את ה-LNA ממקור נפרד*
(USB power bank + DC injector זול) — זה מוציא את הצריכה הזו לגמרי מתקציב
הכוח של ה-Pi. ⚠ **לעולם אל תזין משני מקורות בו-זמנית** (RSP1B + חיצוני) —
זה עלול להזרים זרם בין הספקים. אבל אם ה-Pi כבר שולי גם בלי SATCOM, הפתרון
האמיתי הוא ספק ראוי (הרשמי של Raspberry Pi, 27W) — ר'
[פתרון תקלות](#פתרון-תקלות) למטה.

> ⚠ **אל תסמוך על אזהרת המתח כהגנה.** כשה-power bank עצמו קוטע (הגנת זרם-יתר),
> הוא עושה זאת מיידית — ה-Pi כלל לא מספיק לרשום undervoltage, והדגלים מתאפסים
> בהדלקה הבאה. האזהרות הן רשת ביטחון בלבד; מה שבאמת מגן זה **להוריד צריכה
> מראש**: להשאיר את "⚡ מצב חסכון CPU" דלוק, ולהזין את ה-LNA חיצונית.
>
> **נמדד בשטח (power bank 5V/3A, bias-T כבוי):** `inmarsat-sniffer` לבדו —
> בלי שום bias-T — מספיק כדי לצנוח מ-0% ל-‎100–270%‎ CPU (2-3 ליבות) תוך
> ‎~0.5 שנייה מההפעלה, עם `volts_in` צונח יחד איתו עד ‎4.15–4.55V (מתוך ‎5.0V
> נומינלי) ברצף. הפיי איבד חשמל לגמרי ‎~1–2 שניות אחרי ההפעלה, בשתי בדיקות
> שדה נפרדות. גם ה-baseline לגמרי במנוחה (בלי SATCOM בכלל) הראה `volts_in`
> של ‎4.8–4.9V וקפיצות undervoltage חוזרות — **שרשרת ההזנה שולית באופן כללי**,
> לא רק מול SATCOM.

**🔋 אם `vcgencmd get_throttled` מראה `0x5xxxx` (או יותר גרוע) גם ב-standby
לגמרי, בלי SATCOM בכלל** — זה סימן ששרשרת ההזנה (הבנק/הכבל/המחבר) שולית
**באופן כללי**, לא רק מול SATCOM. אין תוכנה שפותרת את זה; שלוש אופציות
חומרה, מהזולה לרצינית:

1. **נצל יציאת מתח גבוה יותר שכבר יש בבנק שלך.** הרבה power bank עם USB-C
   PD נותנים 5V/3A (‎15W) בפורט אחד, אבל 9V/2A או 12V/1.67A (‎18–20W) באחר —
   ה-Pi 5 עצמו **לא** יכול להשתמש בפרופילים האלה ישירות (הוא תמיד מבקש 5V),
   אבל ממיר **buck** קטן (5V/5A trigger, ~$5–10, יעילות ‎~90%+) בין הבנק
   ל-Pi הופך את ה-18–20W האלה בחזרה ל-‎~5V/3.3–3.6A בפועל — **מרווח ממשי
   יותר, מגרם שכבר יש לך.**
2. **ספק ייעודי 5V/5A (25W)** — הרשמי של Raspberry Pi הוא הבטוח ביותר,
   אבל דורש חשמל רשתי (לא רלוונטי בשטח על סוללה).
3. **מפצל/רכזת USB מוזנת** בין ה-Pi ל-RSP1B — מוציא את צריכת ה-SDR+bias-T
   מהמסלול המשותף עם שאר הלוח לגמרי, במקום לחלוק אותו.

בדוק גם את **הכבל עצמו** — כבל דק/ארוך מפיל מתח אמיתי תחת 3A, ותקלה נפוצה
שמתפספסת כי היא "רק כבל".

**⚠ שונה משאר המצבים: SATCOM לא חוזר אוטומטית אחרי `reboot`.** קול/ACARS/VDL2
שורדים אתחול מחדש (חוזרים למצב האחרון), אבל מצב SATCOM נועד להישאר כבוי עד
כניסה ידנית מפורשת — כדי שה-bias-T לא יידלק בלי בן-אדם בסביבה שיוודא איזו אנטנה
מחוברת כרגע. אחרי `reboot` שהיה במצב SATCOM, פשוט לחץ שוב **📶 SATCOM** (או ⏻).

**שמירה וייצוא:** ההודעות נשמרות ל-`/var/lib/airam/satcom.jsonl` (שורד restart),
וניתן לייצא הכול מכפתורי **CSV/JSON**. שים לב: הודעות SATCOM **בלי** `level`/`snr`/`freq`
— ‏`inmarsat-sniffer` לא חושף אותם ב-feed (לעולם לא ממציאים ערך שאינו נמדד).

**"נעול אבל אין הודעות" — זו לא בהכרח תקלה:** פאנל הכיוון מראה נעילת דמודולטור
**גם באפס הודעות מפוענחות** (זה מה שמאפשר לכוון לפיו מלכתחילה). אם ערוץ נעול
אבל לא מגיעות הודעות אחרי כמה דקות — ייתכן שהלוויין פשוט שקט כרגע, לא שיש תקלה.

> **הערה:** מצב SATCOM אינו נכלל בעורך הסריקה (הוא דורש אנטנה אחרת, אז מחזור אוטומטי
> מולו אינו הגיוני). זהו MVP מכוון.

## מסלולים פעילים ואינדיקציית GPS ✈️📡

כרטיס "מסלולים פעילים · נתב״ג" מציג איזה מסלול משמש כרגע **לנחיתות** ואיזה
**להמראות** (בדרך כלל 26 להמראות), ולצדו אינדיקציית **שיבוש GPS** באזור.

**מאיפה הנתונים?** אף API חינמי לא מדווח "מסלול בשימוש", אז `webtune/adsb.py`
מסיק אותו בעצמו: thread ברקע מושך פעם בדקה את המטוסים סביב נתב"ג ממקור ADS-B
קהילתי חופשי — [adsb.lol](https://api.adsb.lol/docs) (גיבוי אוטומטי:
[adsb.fi](https://github.com/adsbfi/opendata)) — ומזהה מטוסים בגישה סופית
(יורדים, במהירות גישה, עם track בכיוון המסלול). המסלול עם הגישות העדכניות
ביותר הוא הפעיל; בשעות שיא, כשנוחתים על שני מסלולים במקביל, מוצג גם מסלול משני
(למשל `30 +21`). אותו עיקרון, על מטוסים מטפסים, קובע את מסלול ההמראות.

**רשת ביטחון נגד שיבוש GPS 🛰️🛡️** — אזור נתב"ג סובל משיבוש GPS מתמשך:
מטוסים בגישה "קופצים" פתאום מעל לבנון/ירדן או משדרים `NIC=0`, ושאילתה לפי
מיקום הייתה מפספסת אותם. הפתרון מנצל שתי עובדות: ‏(1) שדה ה-**track** והגובה
הברומטרי **שורדים את השיבוש** (הם לא נגזרים מ-GPS), ‏(2) השיבוש **מקומי** —
אז מטוס עם `NIC=0` הוא בעצמו עדות שהוא פיזית קרוב לשדה. לכן: מטוס עם מיקום
אמין מסווג לפי גאומטריית הקו המוארך; מטוס מזויף מסווג **לפי הכיוון בלבד**
(הקורסים בנתב"ג מרוחקים >40°, אז track לבדו מספיק). כשהזיהוי נשען על כיוון
בלבד מוצג חיווי "זוהה לפי כיוון (GPS משובש)", ובכרטיס מוצג מספר המטוסים
המזויפים כרגע באזור.

**שיבוש GPS:** כל מטוס משדר ב-ADS-B את רמת שלמות הניווט שלו (NIC).
כשמערך ה-GPS משובש, מטוסים רבים משדרים NIC נמוך — זו בדיוק השיטה של
[gpsjam.org](https://gpsjam.org/about), רק שכאן היא מחושבת בזמן אמת מאותם
נתונים: אחוז המטוסים מעל 5,000 רגל באזור עם NIC&lt;7, באותם ספים
(🟢 תקין &lt;2% · 🟡 חשד 2–10% · 🔴 שיבוש &gt;10%). זהו אינדיקטור סטטיסטי,
לא מקור רשמי.

- אין אינטרנט / המקור נפל? הכרטיס דוהה עם "ממתין לרשת" — **הרדיו לא מושפע**.
- אין תנועה (לילה)? מוצג המסלול האחרון הידוע וכמה זמן עבר.
- אימות מהיר: כוונן ל-**מגדל 134.600** ושמע איזה מסלול ניתן בקליראנס,
  או הרץ `python3 /opt/airam/webtune/adsb.py` לדו"ח סיווג חי בטרמינל
  (`--selftest` לבדיקה ללא רשת).

## איך זה עובד מתחת למכסה המנוע

- **`webtune/app.py`** — שרת Flask קטן. בכל `POST /api/tune` הוא כותב `/etc/rtl_airband/airband.conf`
  עם ערוץ יחיד ממורכז על התדר הנבחר (ולכן תמיד בתוך החלון), ומריץ `systemctl restart rtl_airband`.
- **`webtune/adsb.py`** — ניתוח ADS-B (מסלול פעיל + GPS) ב-thread נפרד; מגיש את
  `GET /api/airspace` מהזיכרון בלבד, כך שתקלת רשת לא נוגעת בנתיב הרדיו.
- **`config/airband.conf`** — קובץ ברירת מחדל לאתחול ראשון (ATIS 132.5). נדרס ע"י הבורר בכל כיוונון.
- **מצב ACARS:** `airam-web` כותב `/etc/airam/acars.env` ומפעיל את `airam-acars`
  (`acarsdec` דרך `EnvironmentFile`). acarsdec שולח כל הודעה כ-JSON ב-UDP ל-`airam-web`
  (פורט פנימי 5556), והדף מושך מ-`GET /api/acars`. ה-unit מוגדר `Conflicts=rtl_airband`
  => הפעלתו עוצרת אוטומטית את הקול (מקלט אחד).
- **מצב VDL2:** אותו דפוס בדיוק — `airam-web` כותב `/etc/airam/vdl2.env` ומפעיל את
  `airam-vdl2` (`dumpvdl2` דרך `EnvironmentFile`). הפלט זורם כ-JSON ב-UDP (פורט 5557),
  והדף מושך מ-`GET /api/vdl2`. ה-unit מוגדר `Conflicts=rtl_airband airam-acars` =>
  הפעלתו עוצרת אוטומטית את שני הצרכנים האחרים.
- **מצב SATCOM:** אותו דפוס — `airam-web` כותב `/etc/airam/satcom.env` (לוויין +
  bias-tee) ומפעיל את `airam-satcom` (`inmarsat-sniffer` דרך `EnvironmentFile`). הפלט
  זורם כ-JSON ב-UDP (פורט 5558) ל-`GET /api/satcom`. ה-unit `Conflicts` את שלושת
  הצרכנים האחרים.
- **שישה שירותים:** `sdrplay` (שירות ה-API), `rtl_airband` (קול), `airam-web` (הממשק
  והמתזמר), `airam-acars` (ACARS), `airam-vdl2` (VDL2) ו-`airam-satcom` (SATCOM). **אף
  צרכן SDR לא עולה באתחול ישירות** — `airam-web` (שעולה תמיד) קורא את המצב השמור
  מ-`state.json` ומפעיל את השירות המתאים; כך המצב שבחרת שורד reboot, כולל כיבוי.

## פתרון תקלות

| בעיה | בדיקה / פתרון |
|------|----------------|
| הדף לא נטען | `sudo systemctl status airam-web` · `sudo journalctl -u airam-web -f` |
| המכשיר לא מזוהה | `SoapySDRUtil --probe="driver=sdrplay"` — אמור להראות RSP1B. ודא ש-`systemctl status sdrplay` רץ ושה-USB מחובר. |
| אין סאונד | בחר ATIS 132.5 (משדר ברצף). בדוק `journalctl -u rtl_airband -f`. ודא שיש שידור בתדר. |
| `unknown modulation` / קורס ב-NFM | תמיכת NFM כבויה כברירת מחדל בבנייה של RTLSDR-Airband. תעופה היא AM בלבד — בחר **AM**. כדי שאופציית NFM תעבוד, הרץ שוב `sudo ./install.sh` (יבנה מחדש עם NFM אוטומטית). |
| רעש/עיוות חזק / "עומס יתר" | כבה את ה-IF AGC בממשק והורד **RF Gain** (ואז **IF Gain**) עד שחיווי "עומס יתר" נעלם. |
| הסטרים לא חוזר אחרי כיוונון | זה לוקח ~3 שניות; הדף מנסה שוב לבד. אם לא — לחץ ▶ בנגן. |
| latency גבוה (עיכוב בשמיעה) | שני גורמים: (1) Icecast `burst-size=0` — `install.sh` מבטיח זאת גם אם התג חסר או נמצא בהערה בקובץ ברירת המחדל. (2) rtl_airband מקודד MP3 ב-VBR שצונח ל-~1KB/s בשקט => הדפדפן ממלא את ה-buffer ההתחלתי ~30 שניות; ההתקנה בונה מחדש עם **CBR 48kbps** (זרם קבוע 6KB/s) => הנגן מתחיל תוך שניות. **הרץ `sudo ./install.sh` (עדכון)** כדי ששני התיקונים יחולו. כפתור "סנכרן ל-live" בממשק מחזיר ל-live אם הנגן נסחף מאחור. רצפה מעשית בנגן דפדפן: ~2–5 שניות. |
| ניתקתי וחיברתי את ה-SDR | השירותים מתאוששים לבד (`Restart=always`, ללא StartLimit) + כלל udev מפעיל מחדש בחיבור. התאוששות תוך שניות, **באותו מצב** שהיית בו (ACARS/VDL2 replug לא מחזיר לקול — הכלל ניטרלי-מצב). |
| מצב ACARS לא עולה | `sudo journalctl -u airam-acars -f`. ודא ש-`acarsdec` נבנה (`command -v acarsdec`) ושה-SDR פנוי (rtl_airband נעצר). אפשר להריץ ידנית: `sudo systemctl restart airam-acars`. |
| מצב VDL2 לא עולה | `sudo journalctl -u airam-vdl2 -f`. ודא ש-`dumpvdl2` נבנה **עם SoapySDR** (`dumpvdl2 --version` מציין soapysdr) ושה-SDR פנוי. ידנית: `sudo systemctl restart airam-vdl2`. אם מסלול ה-SoapySDR בעייתי על החומרה — יש שורת fallback לדרייבר הנייטיבי בהערה ב-`systemd/airam-vdl2.service`. |
| איפה נשמרות הודעות ה-VDL2 | ב-`/var/lib/airam/vdl2.jsonl` (JSONL, שורד אתחול, retention ~5000). ייצוא: כפתורי **CSV/JSON** בכרטיסיית VDL2 או `GET /api/vdl2/export?format=csv`. |
| מצב SATCOM לא עולה | `sudo journalctl -u airam-satcom -f`. ודא ש-`inmarsat-sniffer` נבנה **עם תמיכת SDRplay** (בלוג הבנייה של `install.sh`: `SDRplay: enabled`) ושה-SDR פנוי. ידנית: `sudo systemctl restart airam-satcom`. |
| אין הודעות SATCOM | ⚠ ודא ש**אנטנת ה-L-band מחוברת ומכוונת ללוויין** (לא אנטנת ה-VHF!) — ר' [מצב SATCOM 📶](#מצב-satcom-). בדוק שה-LNA מוזן (bias-T). עקוב אחרי **פאנל הכיוון** (Eb/No מיטבי + גרף + נעילה פר-ערוץ) בתצוגת SATCOM וכוונן עדין את האנטנה סביב Alphasat (25°E) עד שערוץ נועל — לפני הנעילה אין טעם לחפש הודעות, הבעיה היא הכיוון. |
| **ה-Pi כבה לגמרי (לא reboot) ברגע שנכנסתי ל-SATCOM** | ⚠ כמעט תמיד ספק כוח שולי — bias-T + עליית CPU בו-זמנית חרגו מהתקרה שלו. בדוק `vcgencmd get_throttled` (ביט `0x10000` = undervoltage מאז האתחול — הוכחה ישירה). **power bank ניידים בפרט**: גם עם USB-C PD, רבים נותנים 5V/3A **בלבד** (הפרופילים החזקים שלהם ב-9V/12V, שה-Pi 5 לא משתמש בהם — הוא תמיד מבקש 5V). פתרון מיידי: סמן **"🔌 הזנת LNA חיצונית"** בתצוגת SATCOM ותן ל-LNA מקור נפרד. פתרון יסודי: ספק/בנק שנותן במפורש **5V⎓5A** (25W), לא רק "PD חזק" כללי. |
| אין הודעות ACARS | תקין שיש שקט — ACARS משדר בבזקים. ודא תנועה אווירית סמוכה, אמת את `ACARS_FREQS` מול מקור מקומי, ונסה `ACARS_GAIN` ידני (למשל 40) במקום AGC ב-`/etc/airam/acars.env`. |
| מפת ה-ACARS לא נטענת / ריקה | המפה דורשת **אינטרנט בטלפון** (אריחי OpenStreetMap). בלי חיבור היא נופלת חיננית והמיקומים נשארים כ-📍 בכרטיסים. שים לב: הודעות עם מיקום (ADS-C/CPDLC) **דלילות** ב-נתב״ג — תקין שהמפה מתמלאת לאט או נשארת ריקה לאורך זמן. |
| איפה נשמרות הודעות ה-ACARS | ב-`/var/lib/airam/acars.jsonl` (JSONL, שורד אתחול, retention ~5000 אחרונות). ייצוא מסודר: כפתורי **CSV/JSON** בממשק או `GET /api/acars/export?format=csv`. |
| rtl_airband לא עולה / `ServiceNotResponding` | ה-`sdrplay_apiService` יכול להיראות `active` ב-systemd אך לא להגיב ללקוחות (`SoapySDRUtil --find="driver=sdrplay"` מחזיר `sdrplay_api_ServiceNotResponding`). שער המוכנות (`airam-wait-sdrplay`) מזהה זאת ועושה `systemctl restart sdrplay` אוטומטית. ידנית: `sudo systemctl restart sdrplay && sudo systemctl restart rtl_airband`. |
| התקנת API נכשלה | ודא רשת; אם יצא API חדש, עדכן `SDRPLAY_VER` ב-`install.sh` והרץ שוב. |

## אבטחה ו"בלי סיסמאות"

- **מאזינים:** ללא סיסמה (Icecast פתוח להאזנה ברשת המקומית).
- סיסמת ה-source בין `rtl_airband` ל-Icecast היא ערך פנימי קבוע (`airam`) שנקבע אוטומטית — אתה לא נחשף אליו.
- **שרת הבורר רץ כמשתמש לא-root (`airam`)**: ההתקנה יוצרת משתמש-מערכת ייעודי ונותנת לו
  הרשאת `sudo` ממוקדת **אך ורק** ל-`systemctl restart rtl_airband` (`/etc/sudoers.d/airam`).
  כך פגיעות בשרת הווב לא שוות הרשאות root מלאות.
- **PIN אופציונלי:** כברירת מחדל אין סיסמה (כמו קודם). כדי לדרוש PIN לשינוי תדר/הגדרות,
  ערוך את `/etc/airam/airam.env`, בטל את ההערה מ-`AIRAM_PIN=...` והרץ `sudo systemctl restart airam-web`.
  הדפדפן יבקש את ה-PIN פעם אחת וישמור אותו מקומית. ההאזנה עצמה נשארת חופשית.
- **הגנת CSRF/DNS-rebinding קלה:** בקשות משנות-מצב נדחות אם ה-`Origin` לא תואם ל-`Host`.
- עדיין **מיועד לרשת פרטית מהימנה בלבד**. אל תחשוף את הפורטים 8080/8000 ישירות לאינטרנט;
  לגישה מבחוץ השתמש ב-VPN (WireGuard / Tailscale).

## SDRConnect (אופציונלי)

לחוויית waterfall ויזואלית אפשר להתקין גם **SDRConnect Server** על אותו Pi ולהתחבר מלפטופ —
אך לא בו-זמנית עם `rtl_airband` (RSP אחד = משתמש אחד). ראה [SDRconnect](https://www.sdrplay.com/sdrconnect/).
